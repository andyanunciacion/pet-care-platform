# PAW

Pet-care discovery platform for the Philippines, launching in Angeles City / Region 3. Pet owners find vet clinics and pet services with accurate hours, services, and prices. Clinics without websites get an SEO-indexed page they maintain themselves.

## Design reviews (Impeccable)
The Impeccable plugin (ARCHITECTURE D40) is enabled for this project. Use it on owner-facing and clinic UI, after building a screen and before opening the PR. Target the route or component, e.g. `/impeccable critique apps/web/src/app/(public)/page.tsx`.
- **Use:** `critique` (UX review), `audit` (a11y, performance, responsive), `polish` (final pass), `typeset`, `layout`, `clarify` (copy, against the voice in DESIGN §2.1), `harden` (errors, empty states, long text, i18n), `adapt` (360px to desktop), `optimize` (the performance budget, DESIGN §9).
- **Avoid** `bolder`, `overdrive`, `delight` and `animate` unless a design decision calls for them: they work against "light on data", "calm in emergencies" and the performance budget (DESIGN §2, §9). Also avoid `colorize` and anything that proposes a new palette, font or logo: the placeholder brand is binding until the brand kit (P0-D3).
- Its suggestions are input, not decisions. Anything that changes a UX decision goes into `AI_DOCS/DESIGN.md` first. `/admin` is shadcn-default and desktop-dense by design (UX14), so don't polish it toward the owner style.
- Its hooks scan edited UI files and add reminders (they never block). If a finding is a false positive, record the narrowest exception with `/impeccable hooks ignore-value …` and a reason.
- **Live mode** (`/impeccable live`, with `pnpm dev` running): pick an element in the browser, choose an action, compare three variants on the page, accept one. Config: `apps/web/.impeccable/live/config.json`. While a session runs, it adds a `<script>` for its helper (`localhost:8400`) to `apps/web/src/app/layout.tsx` and wraps the picked element's source in temporary variant markup. Accepting rewrites the variant into normal code with our tokens; ending the session (`live-server stop`) removes the script. Don't commit during a session, and check `git diff` afterwards for leftover `impeccable-` markers.
- Its engine binary downloads once on first use. If that fails with a certificate error (Git's curl and Avast), run the launcher once with `C:\Windows\System32` first on `PATH` (D40).

If code and docs disagree, ask which is right, then update the one that's wrong. When a decision changes, update ARCHITECTURE.md's decision log in the same change.

## Commands
Node 24 (`.nvmrc`; `pnpm install` refuses other versions) and pnpm (exact version pinned in `packageManager`). Run from the repo root.
- `pnpm install`
- First run: `docker compose up -d`, copy each `.env.example` to `.env` (`apps/api`, `apps/web`, `packages/db`), then `pnpm db:migrate`. The API needs `BETTER_AUTH_SECRET` and a Google OAuth client (`GOOGLE_CLIENT_ID` / `_SECRET`, redirect URI `http://localhost:3000/v1/auth/callback/google`) to boot; see `apps/api/.env.example`. Image uploads need the optional `R2_*` variables (a Cloudflare R2 dev bucket; setup steps in `AI_DOCS/github-issues.md`, P1-2d); without them the image screens say storage isn't set up. Its `r2.dev` image URLs don't load on some Philippine networks: turn on Cloudflare WARP to see them
- `pnpm --filter @paw/api promote-admin --email <email> [--role user]`: gives a user `super_admin` (access to `/admin`), or takes it away. They must have signed in once. Writes an `audit_log` entry. On staging, run it through `railway ssh` (steps in `AI_DOCS/github-issues.md`, P0-T6)
- `pnpm dev` / `pnpm build` / `pnpm lint` / `pnpm typecheck`: run in every app and package through Turborepo (cached). `pnpm dev` starts the web app at `http://localhost:3000` and the API at `http://localhost:4000` (OpenAPI docs at `/docs`). Turbo runs tasks in strict env mode: an env var a task reads (e.g. `API_URL` for the web build and typecheck) must be listed in that task's `env` in `turbo.json`, or CI and Vercel don't pass it (`NODE_EXTRA_CA_CERTS` is passed to every task, so antivirus software that re-signs HTTPS, like Avast on this machine, doesn't break the API's calls to R2). Locally the `.env` files hide this, since Next reads them from disk. To check like CI does, move `apps/web/.env` aside and set the variable in the shell
- `pnpm api:generate`: after changing an API route, regenerates `packages/api-client` (`openapi.json` + `src/schema.ts`); commit both. A test fails if they're stale
- `pnpm test`: all tests once (Vitest projects, one per app/package). **Needs the Docker database running**: each package with DB tests gets its own fresh, migrated `paw_test_…` database per run, dropped afterwards (your dev data is never touched). `pnpm test:watch` for watch mode. One package: `pnpm test --project @paw/api`. One file: `pnpm test path/to/file.test.ts`
- `pnpm format` / `pnpm format:check`: Prettier (docs in `AI_DOCS/` are excluded)
- `docker compose up -d`: local Postgres 16 + PostGIS on `localhost:5432`. `docker compose down -v` wipes the data.
- `pnpm db:generate`: after changing tables in `packages/db/src/schema`, writes a new SQL migration to `packages/db/migrations` (review it and commit it). `pnpm db:generate --custom --name=<name>` gives an empty one for hand-written SQL
- `pnpm db:migrate`: applies pending migrations to `DATABASE_URL` (the dev database locally)
- `pnpm db:studio`: browse the dev database at https://local.drizzle.studio
- `pnpm --filter @paw/db psgc:sql --xlsx <file> --province <code> [--huc <code>] --out <migration.sql>`: writes a province's PSGC areas into a custom migration, from the PSA's PSGC datafile (download it from psa.gov.ph; `*.xlsx` is gitignored). Reference data (PSGC, species, categories) ships as migrations (ARCHITECTURE D27)

CI (`.github/workflows/ci.yml`) runs `pnpm format:check`, `lint`, `typecheck`, `test` and `build` on every PR, against a Postgres+PostGIS service container. The job is named `checks`; branch protection on `develop` and `production` requires it. Run the same commands locally before pushing.

Adding an app or package: name it `@paw/<name>`, extend `@paw/config/tsconfig.base.json`, add an `eslint.config.js` extending `@paw/config/eslint` (see `packages/config/eslint.config.js`), give it `lint` and `typecheck` scripts, and take shared tool versions from the pnpm catalog (`"typescript": "catalog:"`, defined in `pnpm-workspace.yaml`).

TypeScript runs as-is (Node's type stripping, no build step; ARCHITECTURE D15): outside `apps/web`, relative imports use the `.ts` extension (`import { buildApp } from './app.ts'`), and TS-only runtime syntax (`enum`, `namespace`, constructor parameter properties) isn't allowed. Use `as const` objects or string-literal unions instead of enums.

API conventions (`apps/api`): env vars are declared and validated in `src/env.ts`; routes are Fastify plugins with Zod schemas (see `src/routes/health.ts`); errors are RFC 9457 `application/problem+json` (`src/errors.ts`; throw `httpError(status, detail)` for 4xx, plus `fieldErrors` (`[{ pointer: '/slug', message }]`) when specific body fields are to blame, so forms show them next to the field); tests build the app with `buildApp()` and call it with `app.inject()`. Route files stay thin: queries, writes and their Zod input/response schemas live in `src/services/*`. Every write runs in `db.transaction` and calls `recordAudit(tx, …)` with `diffFields(before, after, fields)` from `src/audit.ts` in the same transaction (an empty diff records nothing). Unique slugs are enforced by the database: catch the violation with `isUniqueViolation(error, constraint)` and answer 409. Responses send timestamps as ISO strings (`z.iso.datetime()`), not `Date`. Child rows (services, products, images) are audited on their parent branch or business (D36). Image files go through the `PhotoStorage` interface (`src/storage.ts`: R2, or `createMemoryStorage()` in tests, passed as `buildApp({ env, storage })`); the upload flow is D38. `httpError()` messages reach the client even for a 5xx (e.g. 503 "storage isn't set up"); any other 5xx is sent as a plain 500. The CSV import (`src/services/imports.ts`, D39) checks rows with the same Zod schemas as the admin forms (`CreateBusinessSchema`, `CreateBranchSchema`, `ReplaceHoursSchema`): a new rule added there applies to imports too. A new column needs `IMPORT_COLUMNS`, `AI_DOCS/csv-import.md` and the template (`apps/web/public/templates/paw-listings-template.csv`; a test checks the template's header).

Auth (`apps/api`, ARCHITECTURE §7): Better Auth (`src/auth.ts`) serves `/v1/auth/*` with its own JSON shapes; keep those routes out of OpenAPI. PAW ops routes go inside the `/v1/admin` plugin (`src/routes/admin/index.ts`), whose `onRequest` hook runs `requirePlatformRole('super_admin')` before every route in it (and in the child plugins it registers) and sets `request.sessionUser` (read it with `sessionUserOf(request)`). Never register an admin route outside that plugin; `admin.test.ts` checks every `/v1/admin/*` path in the OpenAPI spec answers 401/403. Tests sign in with `sessionCookie(app, userId)` from `src/testing.ts` (after `insertTestUser`). Better Auth's in-memory rate limiter is shared by every app in a test file, so tests that hit `/v1/auth/*` many times pass their own `remoteAddress` to `app.inject()`.

Database conventions (`packages/db`): tables are defined in `src/schema` and exported from `src/schema/index.ts`. Column names are written camelCase in TypeScript and become snake_case in SQL automatically (`casing: 'snake_case'`). Apps get a connection with `createDatabase()` from `@paw/db`. A package that needs a database in tests adds `globalSetup: ['@paw/db/testing/global-setup']` to its `vitest.config.ts` and reads the URL with `testDatabaseUrl()` from `@paw/db/testing`. New tables use `id()` and `...timestamps` from `src/schema/columns.ts` (UUID v7 ids made by the database); map points use `geographyPoint()` (`{ lng, lat }`). drizzle-kit quotes custom column types in generated SQL (`"geography(Point, 4326)"`), so unquote them by hand in the migration. Tests insert rows with the helpers in `@paw/db/testing` (`insertTestUser`, `insertTestBusiness`, `insertTestBranch`, `insertTestSpecies`, `insertTestCategory`, fake PSGC areas) and check database rules with `violatedConstraint()`. Test files share one database per run and run in parallel, so never assume a table holds only your rows: test rows use unique or made-up values (never real reference data like the synonym "kapon"), and tests of the real reference data skip test rows (codes starting with `category_` / `species_`, PSGC codes starting with `99`).

Domain logic (`packages/domain`): pure functions with no database or I/O, shared by the API, worker and web app; unit-tested without Docker. Hours (`openStatus`, `isOpenNow`, `closesAt`, `nextOpening`) and `freshness` take the current instant as a parameter (never read the clock inside), so tests pin exact Manila times. Their rules are ARCHITECTURE D28–D29. `weeklyHoursIssues` / `dayIntervalsIssues` check hours as entered (overlaps, including past midnight); the API and the hours editor both use them, so the browser shows the API's errors before saving (D35). `parseDayHours` reads hours as typed in a spreadsheet ("8am-12nn, 1pm-5pm", "closed") for the CSV import. Also here: `slugify` / `SLUG_PATTERN` (the database's slug check imports it), `normalizePhPhone` (→ E.164), `parsePesos` / `formatPesos` (typed pesos ↔ integer centavos), the image upload limits and `fitWithin` (`media.ts`, D38), `parseLatLng` / `isInPhilippines`, and `BUSINESS_TYPE_RULES` (vet-only rules such as the emergency flags, ARCHITECTURE §5.3).

Web conventions (`apps/web`, Next.js 16 App Router): **read the version-matched docs in `apps/web/node_modules/next/dist/docs/` before Next.js work**; this version differs from older training data. Next bundles the app, so imports are extensionless and use the `@/` alias (`@/components/…`). Pages are Server Components that fetch through `apiClient()` (`src/lib/api.ts`) and never touch the database. Every UI string lives in `messages/en.json` and is read with `getTranslations()` from `next-intl/server` (keys are type-checked). Colors, radius and fonts come only from the tokens in `src/app/globals.css` (`bg-primary`, `text-status-open`, …), never raw values. Add shadcn components from `apps/web` with `pnpm dlx shadcn@latest add <name>`; they land in `src/components/ui`. Type page props by hand (`{ params: Promise<{ id: string }> }`), not with Next's global `PageProps<'/route'>`: that type only exists after `next typegen`, which CI's lint job doesn't run (locally `.next/` hides this). Routes: public pages in the `src/app/(public)` route group; `/login` in `(auth)`; `/dashboard`, `/admin` and `/login` are `noindex`. `next.config.ts` rewrites `/v1/*` to the API (ARCHITECTURE D31), so browser code calls `/v1/…` on its own origin, never `API_URL`. Every `/admin` page **and Server Action** starts with `await requireAdmin()` (`src/lib/admin-session.ts`), not just the layout: layouts don't re-run on client-side navigation, and actions are public POST endpoints. It forwards the user's cookie to the API and redirects to `/login` if needed. Admin pages read with `adminApi()` + `dataOrNotFound()` / `dataOrThrow()` (`src/lib/admin-api.ts`); request/response types come from `src/lib/admin-types.ts` (derived from the generated client). Admin writes are Server Actions (`src/app/admin/actions.ts`, ARCHITECTURE D34) called from Client Component forms with a typed body; they return a `FormState` (`src/lib/form-errors.ts`) that maps the API's problem `errors[].pointer` onto fields. Client Components needing many strings are wrapped in a provider that ships only their namespaces (`AdminFormMessages`). Reads that follow user input in the browser (the PSGC pickers) use `browserApi` (`src/lib/browser-api.ts`, same-origin `/v1`). Maps use MapLibre (D7), loaded with a dynamic `import()` and `setWorkerUrl(new URL('maplibre-gl/dist/maplibre-gl-worker.mjs', import.meta.url).href)` (v6 can't find its worker after bundling otherwise; see `components/admin/location-picker.tsx`).

## Engineering conventions
- TypeScript `strict`; no `any` (use `unknown` + narrowing). Zod validates every boundary (HTTP input, env vars, external APIs, CSV imports).
- **Business logic lives in `apps/api` / `packages/domain`.** Web and mobile are clients and never talk to the database directly.
- Authorization is checked in the API service layer (`platform_role` + `business_member.role`), never only in the UI.
- Schema changes go only through Drizzle migrations. Never edit production data by hand.
- Store times in UTC; business hours are wall-clock times in `Asia/Manila`. Money is integer centavos (PHP). Phones are E.164 (`+63…`). Addresses carry PSGC codes.
- Public data hangs off **branch**, not business (hours, address, contacts, services).
- Launch is vets only, but schema, API, and code say `business`, never `clinic`. "Clinic" is UI copy for the vet type. Vet-only rules (PRC, emergency flags) depend on the business type (ARCHITECTURE §5.3).
- No personal data in logs or analytics events. Claim documents live in the private bucket, accessed only through signed URLs.
- Write tests with each change: unit tests for domain logic (especially hours/"open now"), integration tests for API routes against real Postgres+PostGIS.
- Every write from `/dashboard` or `/admin` records an `audit_log` entry.

## Domain glossary
- **Business**: a clinic/groomer/shop brand or owner. **Branch**: a physical location with its own hours and contacts.
- **Claim**: a business owner taking over a PAW-seeded listing (verified by phone + PRC license + permit) → `claim_status = verified`.
- **Hours confirmation**: the clinic (or PAW ops) confirming hours are still correct → `branch.hours_confirmed_at`.
- **Correction report**: a public "report incorrect info" submission.
- **PAW ops / super admin**: the founder's internal role (`/admin`). **Clinic dashboard**: `/dashboard`.
